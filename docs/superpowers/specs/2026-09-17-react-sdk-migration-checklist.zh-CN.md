# React SDK 迁移：更新清单

## 背景与证据

同事建议 React quickstart 使用 `agora-rtc-react`，并以 Agents NextJS 示例说明
React Strict Mode 双挂载防护及 Next.js 动态加载。反馈指出的是集成时应注意的做法，
并没有报告本项目已发生双挂载或 hydration 故障。

本清单基于源码检查，不代表已在当前浏览器中复现问题或完成双客户端媒体验证。
SDK 迁移方向已经确定；具体实现与验收证据仍需在发布前落实。

## 更新清单

1. **SDK 选型与生命周期所有权：已决定迁移。** 将应用直接集成
   `agora-rtc-sdk-ng` 的方式迁移为 `agora-rtc-react` hooks 和 Provider。
   明确 client 创建、加入/退出、发布/取消发布、本地轨道、远端播放各自只有一个
   所有者，不保留一套并行的手动 `RtcSession` 生命周期。除非另行决定，保留现有
   房间 URL、token 接口、字符串用户账号及通话操作流程。

2. **React Strict Mode 与重新挂载：迁移时的预防性检查，并非已报告故障。**
   在适用的挂载时 hook 场景参考 Agents NextJS 示例，确保开发环境的双挂载不会
   产生重复 client、重复 join 或重复设备轨道。同时检查真实的离开页面与再次进入。
   当前项目由用户点击后才开始 join，没有已观察到的重复 join 事件。

3. **SSR 与 hydration：保留并验证现有边界。** 当前房间通过 Client Component
   内的 `next/dynamic` 和 `ssr: false` 加载 RTC 组件。迁移后 Provider 和所有
   仅能在浏览器使用的 SDK import 仍须位于该边界内。完成 Next.js 构建及真实
   浏览器 hydration 检查。同事的反馈不证明当前已经发生 hydration 故障。

4. **异步 join 的取消与清理：独立的源码推断风险。** 当用户在 token 请求或
   SDK join 尚未完成时离开页面，当前手动流程可能在组件卸载后继续执行。
   需要验证该场景，并确保迁移后的流程不会启动或遗留孤立会话，join 失败时
   也应正确清理。这不是同事报告的故障，本次检查也未在浏览器中复现。

5. **RTC 行为保持：迁移验收项。** 保留以相同房间和用户账号续期 token、
   分别处理音视频、单个设备不可用时仍可使用另一种媒体、仅在点击 Join Call
   后访问设备、静音、切换设备、远端离开及资源释放。不要顺带引入 Agent、
   RTM、录制、身份认证或持久化功能。

6. **验证与文档：发布条件。** 为生命周期及失败边界补充针对性回归测试，
   通过 `pnpm run verify` 执行 doctor、lint、typecheck、build，并在浏览器中
   检查改动过的流程。静态检查及单客户端 join 不等于 RTC 完整成功：需要两个
   独立客户端以不同账号进入同一房间，确认双方均收到远端音频和视频。同步
   README、ARCHITECTURE、AGENTS、RECIPE、受影响的 L1 文档、依赖声明，
   以及因实质性 UI 变化而失效的截图。

## 范围边界

本文仅列出待办范围，不授权提交、推送、创建 PR、部署或其他远端写操作。
第 2、3 项是迁移时应保持的防护要求，不是对现有生产故障的诊断；本文不声称
已获得运行时媒体验证结果。
